# UI/UX 体验审计（ui-ux-audit）

**前提判断**：先确认项目是否有图形界面。没有界面（纯库/CLI/SDK）时，第 9 节应写"本项目无图形界面，此项不适用"，并把 UI 权重转为"CLI/API 体验"或标注不适用，**不能空着，也不能硬打分**。

---

## 1. 能否实际打开界面

| 条件 | 做法 | 结论等级 |
|---|---|---|
| 有 `npm run dev` / `index.html` / 可执行安装包 | 启动并用浏览器或桌面截图实测 | L1 实测 |
| 只有源码与截图 | 依据组件代码 + README 截图评审 | L2/L4 |
| 只有代码 | 只评"实现层面"（有没有 loading/error 状态、是否响应式） | L3 推断 |

用 `browser` 能力打开页面时，必须实际截图看渲染结果，不能只看代码断言"设计现代"。

---

## 2. 视觉与布局

- **层级**：是否有清晰的视觉主次（标题/正文/辅助信息字重与色阶）
- **栅格**：间距是否成体系（4/8px 基准），还是随手 13px、27px
- **对齐**：卡片内边距一致、表单标签对齐
- **留白**：是否拥挤（信息密度过高）或空旷（大片无意义空白）
- **色彩**：主色/语义色（成功/警告/错误）是否统一；对比度是否达标（正文 ≥4.5:1）
- **字体**：字号阶梯是否有层级；中英文混排行高；是否用了系统字体栈
- **图标**：是否同一套（混用 emoji + iconfont + svg 是常见问题）、线宽一致
- **一致性**：同类操作在不同页面是否长得一样（按钮样式、确认弹窗）

---

## 3. 交互与状态（最容易被忽略、也最影响体验）

必须逐个检查"四种状态"是否存在：

| 状态 | 缺失表现 | 检查点 |
|---|---|---|
| Loading | 点击后无反应，用户重复点击 | 有无骨架屏/spinner/禁用按钮 |
| Empty | 空白页面，以为坏了 | 有无空状态插画 + 引导操作 |
| Error | 白屏或 `undefined` | 有无错误提示 + 重试入口 |
| Success | 操作后无反馈 | 有无 toast/跳转/状态更新 |

其它：
- 破坏性操作是否有二次确认 / 可撤销
- 表单校验时机（失焦 vs 提交）、错误信息是否指明字段
- 键盘可达性（Tab 顺序、Enter 提交、Esc 关闭）
- 焦点管理（弹窗打开后焦点是否进入、关闭是否归位）
- 长列表滚动位置保持、返回后状态恢复

---

## 4. 响应式与适配

- 断点：<768 / 768–1024 / >1024 是否有布局变化
- 触控目标 ≥44×44px（移动端）
- 横向滚动是否意外出现（固定宽度容器）
- 超长文本：是否截断/换行（`ellipsis`、`break-word`），而不是撑破布局
- 图片/表格在小屏是否溢出

**桌面软件额外项**
- 窗口自由缩放是否布局错乱（最小尺寸是否设定）
- 高 DPI（125%/150%/200%）下是否模糊（未用矢量/未做 DPI 感知）
- 系统托盘、快捷键、原生菜单、文件拖放是否支持
- 多显示器不同缩放比例下拖动窗口是否异常
- 暗色模式是否跟随系统

**移动应用额外项**
- 小屏（320pt）与大屏（折叠屏/平板）适配
- 安全区域（刘海/底部手势条）避让
- 横竖屏切换状态保持
- 手势冲突（侧滑返回 vs 列表横滑）

---

## 5. 可访问性（a11y）

- 图片 `alt`、图标按钮 `aria-label`
- 语义化标签（`button` 而非 `div onclick`）
- 表单 `label` 与 `for` 关联
- 颜色不是唯一信息载体（错误不能只靠红色）
- 焦点可见（不要 `outline: none` 而无替代）
- 动态内容变更有无 `aria-live`

---

## 6. 评分口径（10 分）

| 分数 | 标准 |
|---|---|
| 9–10 | 四态齐全、响应式完善、a11y 基本达标、视觉体系统一，实测体验流畅 |
| 7–8 | 主流程体验良好，个别状态缺失或细节不一致 |
| 5–6 | 能用但明显粗糙：缺 loading/empty、样式不统一、移动端错位 |
| 3–4 | 多页面布局错乱、频繁无反馈、视觉混乱 |
| 0–2 | 界面不可用或仅原型 |

**只评代码未实测 → 分数上限 6 分，且必须标注"未实测"。**

---

## 7. 输出要求

- 每条问题附：页面/组件路径 + 截图或代码位置 + 复现步骤 + 影响
- 建议要具体到"改成什么"，例如："把 `color: #999` 改为语义变量 `--text-secondary`，对比度从 2.8:1 提到 4.6:1"
- 不要用"设计不够现代"这种无法验证的判断；给可核对的差异
