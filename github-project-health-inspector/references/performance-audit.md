# 性能审计规程（performance-audit）

**第一原则：没有测量就没有数字。** 你不能运行它，就只能说"结构上有风险"，不能编造 "首屏 1.2s"、"QPS 3000"。

---

## 1. 两种模式，结论写法完全不同

| 模式 | 前提 | 可以说 | 不可以说 |
|---|---|---|---|
| 实测模式 | 成功在隔离副本中安装并运行（`docker`/`npm run dev`/`pytest`） | 具体耗时、内存峰值、包体积、Lighthouse 分数 | — |
| 静态模式（默认） | 无法运行 | "N+1 查询风险"、"同步阻塞主线程"、"打包体积可能偏大（因为引入了 X）" | 任何精确数字、任何"实测"措辞 |

判断能否运行的标准：有锁文件 + 有构建脚本 + 依赖可下载 + 无需私密配置。四条缺一条就老实走静态模式。

---

## 2. 静态模式下可判定的真实瓶颈

**后端**
- 循环内查库（N+1）：`for x in items: db.query(...)`
- 无分页的全表查询：`SELECT * FROM t` 无 `LIMIT`
- 缺索引的高频查询：`WHERE user_id = ?` 但 schema 无该索引
- 同步阻塞放在请求路径：请求里做文件压缩/图片处理/大模型调用
- 每次请求都重建连接池 / 每次读同一份大文件
- 缓存策略：有无缓存层、TTL 是否合理、是否缓存了用户私有数据
- 无超时配置：`requests.get(url)` 无 `timeout`
- 无并发控制：线程池大小、队列无界
- 序列化开销：返回整个 ORM 对象含关联、大 JSON 深拷贝

**前端**
- 首屏加载全部模块（无路由级 code splitting）
- 图片无懒加载、无响应式尺寸、未用现代格式
- 引入整包而非按需（`import _ from 'lodash'`）
- 大依赖进主 chunk（moment、echarts 全量）
- 列表无虚拟滚动（渲染上千 DOM）
- 每次 render 重建大对象/函数（无 memo）
- 同步长任务阻塞主线程（大数组计算在主线程）
- 无 `key` 或 `key=index` 导致全量重排

**数据库**
- 迁移缺索引、`SELECT *`、`OFFSET` 深分页
- 事务范围过大（事务里做网络调用）
- 连接未复用

**构建/依赖体积**
- 依赖数量、是否引入多个功能重叠的大包（moment+dayjs、axios+node-fetch）
- 是否提交了构建产物（`dist/`、`build/`）导致仓库膨胀
- 是否存在超大文件（>300KB 源码）

## 3. 如果能真跑，测什么（最少四条）

```bash
# 1. 安装与构建耗时/是否成功
time npm ci && time npm run build

# 2. 产物体积
du -sh dist/ ; ls -lh dist/assets | sort -k5 -h | tail -10

# 3. 启动时间（后端/CLI）
/usr/bin/time -v python app.py   # 关注 Maximum resident set size

# 4. 测试耗时与失败
npm test -- --runInBand
```
前端再加 Lighthouse（若有 Chrome）：`npx lighthouse http://localhost:3000 --output=json`。

**记录格式**：`环境（机器/版本）+ 命令 + 结果 + 时间`。没有环境的性能数字一律无效。

## 4. 报告写法对照

❌ 错：
> 项目性能优秀，接口响应约 50ms，首屏 1.1s。

✅ 对：
> **静态分析**：`api/list.py:44` 在循环内逐条查询用户表，列表 50 条时产生 51 次 SQL（N+1）。项目未提供可运行的本地环境配置（缺 `.env.example` 中的必需项），因此**未做实测**，此处为代码级推断。同类项目通常用 `join` 或 `IN` 批量查询，可把 51 次降为 1 次。

---

## 5. 优化建议必须可执行

每条建议写清：**改哪里 → 怎么改 → 预期收益（定性/有依据的定量） → 风险**。

| 瓶颈 | 改法 | 预期 | 风险 |
|---|---|---|---|
| N+1 查询 | 改批量 `IN` 查询 + 预加载关联 | 查询数从 O(n) 降到 O(1) | 需处理关联为空 |
| 首屏包过大 | 路由级 `lazy` + 分包 | 首屏 JS 显著下降（需构建后核对） | 首屏切换有加载态 |
| 列表卡顿 | 虚拟滚动 | DOM 节点恒定在可视区 | 高度需可估算 |
| 无缓存 | 加 Redis + 合理 TTL | 热点读下降 | 一致性窗口 |

**禁止**给出"建议优化数据库"、"建议使用缓存"这类无法执行的空话。
